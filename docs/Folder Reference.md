# Folder Reference

This document describes the purpose and responsibility of every directory used by MCF.

All framework components are organized under a single root directory.

```text
app/MCF
```

Each folder has a single responsibility.

---

# Root Structure

```text
app/MCF
├── Assets/
├── Database/
│   ├── Factories/
│   ├── Migrations/
│   ├── Models/
│   └── Seeders/
├── Layouts/
├── Mail/
├── Middleware/
├── Modules/
├── Notifications/
├── Rules/
├── mcf_routes.php
└── README.md
```

---

# Assets

```text
app/MCF/Assets
```

## Purpose

Stores static assets used by the framework or application.

Typical assets include:

- CSS
- JavaScript
- Images
- Icons
- Fonts
- Static resources

The directory exists as part of the framework architecture and may be expanded in future versions.

---

# Database

```text
app/MCF/Database
```

## Purpose

Contains every database-related component generated by MCF.

Structure:

```text
Database
├── Factories
├── Migrations
├── Models
└── Seeders
```

Keeping database components together simplifies maintenance and improves discoverability.

---

# Models

```text
app/MCF/Database/Models
```

## Purpose

Contains Eloquent models.

Generated using:

```bash
php artisan mcf:make:model
```

Models represent application entities and business data.

Examples:

- User
- Product
- Invoice
- Customer
- Order

MCF generates models inside this directory instead of Laravel's default `app/Models`.

---

# Migrations

```text
app/MCF/Database/Migrations
```

## Purpose

Contains database migration files.

Generated using:

```bash
php artisan mcf:make:migration
```

Supports all standard Laravel migration options.

Examples:

- Creating tables
- Modifying tables
- Renaming tables
- Dropping tables

---

# Factories

```text
app/MCF/Database/Factories
```

## Purpose

Contains Eloquent factories.

Generated using:

```bash
php artisan mcf:make:factory
```

Factories are primarily used for:

- Testing
- Database seeding
- Sample data generation

---

# Seeders

```text
app/MCF/Database/Seeders
```

## Purpose

Contains database seed classes.

Generated using:

```bash
php artisan mcf:make:seeder
```

Seeders populate the database with initial or sample data.

MCF intentionally does not generate a `DatabaseSeeder`.

Applications are free to organize seeding according to their own requirements.

---

# Layouts

```text
app/MCF/Layouts
```

## Purpose

Contains reusable application layouts.

Examples include:

- Dashboard layouts
- Authentication layouts
- Shared interfaces
- Administrative layouts

This directory is reserved for reusable presentation structures.

---

# Mail

```text
app/MCF/Mail
```

## Purpose

Contains Laravel Mailable classes.

Generated using:

```bash
php artisan mcf:make:mail
```

MCF generates only the Mailable class.

It intentionally does not generate:

- Blade templates
- Markdown templates
- Email layouts

These resources can be created manually if required.

---

# Middleware

```text
app/MCF/Middleware
```

## Purpose

Contains HTTP middleware.

Generated using:

```bash
php artisan mcf:make:middleware
```

Typical middleware responsibilities include:

- Authentication
- Authorization
- Request validation
- Logging
- Request filtering

---

# Modules

```text
app/MCF/Modules
```

## Purpose

Contains business modules.

Modules are the primary organizational unit within MCF.

Each module represents an independent business feature.

Examples:

```text
Modules
├── Users
├── Orders
├── Products
├── Reports
└── Inventory
```

Modules should encapsulate business functionality while remaining as independent as practical.

Generated using:

```bash
php artisan mcf:make:module
```

---

# Notifications

```text
app/MCF/Notifications
```

## Purpose

Contains Notification classes.

Generated using:

```bash
php artisan mcf:make:notification
```

Notifications remain independent from the Mail system.

MCF intentionally generates only Notification classes.

Mail templates and Markdown views are outside the responsibility of this generator.

---

# Rules

```text
app/MCF/Rules
```

## Purpose

Contains reusable validation rules.

Generated using:

```bash
php artisan mcf:make:rule
```

Rules encapsulate reusable validation logic that can be shared across the application.

Examples:

- StrongPassword
- ValidNationalId
- UniqueUsername
- ValidPhoneNumber

---

# Routes

```text
app/MCF/mcf_routes.php
```

## Purpose

Contains routes managed by MCF.

Separating framework routes from Laravel's default route files keeps routing organized and prevents unnecessary growth of:

```text
routes/web.php
```

All framework routes should be registered through this file unless a module introduces its own routing mechanism in future versions.

---

# README

```text
app/MCF/README.md
```

## Purpose

Provides a lightweight quick reference for developers working inside the application.

Unlike the framework documentation, this README focuses only on commonly used Artisan commands and basic framework usage after installation.

---

# Directory Design Principles

Every directory inside MCF follows these principles.

- Single Responsibility
- Predictable Location
- Clear Naming
- Modular Organization
- Laravel Compatibility

Each directory exists for one purpose only.

Keeping responsibilities isolated improves maintainability, scalability, and overall project organization.
