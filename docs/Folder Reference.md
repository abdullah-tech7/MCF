# Folder Reference

This document describes the purpose and responsibility of every directory used by MCF.

All framework components are organized under a single root directory.

```text
app/MCF
```

Every directory has one clear responsibility and follows MCF's Workflow-driven architecture.

---

# Root Structure

```text
app/MCF
├── Base
│   ├── MfcController.php
│   ├── MfcRequest.php
│   ├── MfcService.php
│   └── MfcPolicy.php
├── Database
│   ├── Factories
│   ├── Migrations
│   ├── Models
│   └── Seeders
├── Mail
├── Middleware
├── Modules
├── Notifications
├── Rules
├── mcf_routes.php
└── README.md
```

MCF intentionally keeps the framework structure compact and predictable.

---

# Base

```text
app/MCF/Base
```

## Purpose

Contains the shared base classes used by every generated Workflow.

Structure:

```text
Base
├── MfcController.php
├── MfcRequest.php
├── MfcService.php
└── MfcPolicy.php
```

These classes provide the common architectural foundation for generated Controllers, Requests, Services, and Policies while keeping framework behavior centralized.

---

# Database

```text
app/MCF/Database
```

## Purpose

Contains every database-related component generated by MCF.

Structure:

```text
Database
├── Models
├── Migrations
├── Factories
└── Seeders
```

Keeping database components together simplifies maintenance while keeping them isolated from Laravel's default directories.

---

# Models

```text
app/MCF/Database/Models
```

## Purpose

Contains every Eloquent Model generated by MCF.

Generated using:

```bash
php artisan mcf:make:model
```

Models represent application entities.

Examples:

- User
- Product
- Order
- Invoice
- Customer

Models are shared across the application and are not owned by individual Modules or Workflows.

---

# Migrations

```text
app/MCF/Database/Migrations
```

## Purpose

Contains database migration files.

Generated using:

```bash
php artisan mcf:make:migration
```

Supports Laravel's standard migration features including:

- Creating tables
- Modifying tables
- Renaming tables
- Dropping tables

---

# Factories

```text
app/MCF/Database/Factories
```

## Purpose

Contains Eloquent Factories.

Generated using:

```bash
php artisan mcf:make:factory
```

Factories are commonly used for:

- Testing
- Database seeding
- Sample data generation

---

# Seeders

```text
app/MCF/Database/Seeders
```

## Purpose

Contains database Seeders.

Generated using:

```bash
php artisan mcf:make:seeder
```

Seeders populate databases with initial or sample data.

MCF intentionally does not generate a `DatabaseSeeder`.

Applications are free to organize seeding as needed.

---

# Mail

```text
app/MCF/Mail
```

## Purpose

Contains Laravel Mailables.

Generated using:

```bash
php artisan mcf:make:mail
```

Only the Mailable class is generated.

Blade templates, Markdown templates and email layouts remain under the developer's control.

---

# Middleware

```text
app/MCF/Middleware
```

## Purpose

Contains HTTP Middleware.

Generated using:

```bash
php artisan mcf:make:middleware
```

Typical responsibilities include:

- Authentication
- Guest access
- Localization
- Logging
- Rate limiting
- Request filtering

Business logic should never exist inside Middleware.

---

# Modules

```text
app/MCF/Modules
```

## Purpose

Contains every Module in the application.

Modules are organizational boundaries.

Each Module groups related Workflows belonging to the same business domain.

Example:

```text
Modules
├── Users
│   ├── Authentication
│   ├── Profile
│   └── UserManagement
│
├── Shop
│   ├── Products
│   ├── Cart
│   └── Checkout
│
└── Shared
    └── Layout
```

Modules organize Workflows.

They do not contain business logic themselves.

Generated using:

```bash
php artisan mcf:make:module
```

---

# Workflow

Every Workflow lives inside a Module.

Example:

```text
Users
└── Authentication
```

A Workflow owns everything required to implement one business capability.

Typical structure:

```text
Authentication
├── AuthenticationController.php
├── AuthenticationRequest.php
├── AuthenticationService.php
├── AuthenticationPolicy.php
├── AuthenticationRoutes.php
├── Views
├── Lang
└── README.md
```

Generated components inherit from the shared base classes located in:

```text
app/MCF/Base
```

Each Workflow is completely self-contained.

---

# Layout Workflow

MCF does not provide a dedicated Layout directory.

Instead, Layout is implemented as a normal Workflow.

Default installation:

```text
Shared
└── Layout
```

Generated using:

```bash
php artisan mcf:make:workflow:layout Shared Layout
```

Generated Controllers return:

```php
return view('Shared::Layout.index');
```

Shared Blade components are referenced using:

```blade
@include('Shared::Layout.Components.head')
```

Responsibilities include:

- Application layout
- Header
- Footer
- Sidebar
- Navigation
- Shared Blade components

Developers may rename, replace or recreate the Layout Workflow at any time.

# Rules

```text
app/MCF/Rules
```

## Purpose

Contains reusable validation Rules.

Generated using:

```bash
php artisan mcf:make:rule
```

Rules encapsulate reusable validation logic shared across multiple Workflows.

Examples:

- StrongPassword
- ValidNationalId
- UniqueUsername
- ValidPhoneNumber

---

# Routes

```text
app/MCF/mcf_routes.php
```

## Purpose

Registers every Workflow Route definition.

Each generated Workflow automatically registers its Route definition through this central entry point.

Route names should follow the MCF naming convention.

Example:

```text
shared.userManagement.index
```

Keeping Workflow Routes separate from Laravel's default routing helps large applications remain organized.

# Assets

MCF does not provide a custom asset directory.

Shared assets should use Laravel's standard structure.

Static assets:

```text
public/
```

Uploaded files:

```text
storage/
```

This follows Laravel conventions and avoids introducing an additional asset system.

---

# Directory Design Principles

Every directory inside MCF follows the same architectural principles.

- Single Responsibility
- Predictable Location
- Workflow-Driven Organization
- Modular Design
- Laravel Compatibility

Every generated Workflow builds on the shared foundation provided by the `Base` directory while remaining fully self-contained.

Every directory exists for one purpose only.

Keeping responsibilities isolated makes applications easier to understand, maintain, and scale.
