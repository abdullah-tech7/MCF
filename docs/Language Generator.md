# Language Generator

MCF organizes localization around Workflows rather than a single global language directory.

Every Workflow owns its own translation resources, allowing features to remain completely self-contained and portable.

The Language Generator automates the creation and management of these translation resources.

---

# Philosophy

Localization should belong to the feature that owns the text.

Instead of placing all translations into one large directory, MCF stores translations alongside their corresponding Workflow.

Example:

```text
Users
└── Profile
    └── Lang
```

This approach keeps every feature independent and easier to maintain.

---

# Why Workflow-Based Localization?

Traditional applications often collect every translation inside one global directory.

As projects grow, this directory becomes increasingly difficult to maintain.

MCF distributes localization across Workflows.

Benefits include:

- Better organization.
- Feature isolation.
- Easier maintenance.
- Improved portability.
- Simpler refactoring.

Translations move together with the feature they belong to.

---

# Generate Language Resources

Generate a new language.

```bash
php artisan mcf:lang:make <locale>
```

Example:

```bash
php artisan mcf:lang:make ar
```

The generator creates translation resources for every existing Workflow.

---

# Generate for a Module

Generate language resources for one Module only.

```bash
php artisan mcf:lang:make <locale> <module>
```

Example:

```bash
php artisan mcf:lang:make ar Users
```

Only Workflows inside the specified Module are affected.

---

# Generate for a Workflow

Generate language resources for one specific Workflow.

```bash
php artisan mcf:lang:make <locale> <module> <workflow>
```

Example:

```bash
php artisan mcf:lang:make ar Users Profile
```

Only the selected Workflow receives the new localization resources.

---

# Generated Structure

Every Workflow contains its own language directory.

Example:

```text
Users
└── Profile
    └── Lang
```

Each supported locale is generated inside that directory.

Example:

```text
Lang
├── en
└── ar
```

This structure remains identical across all Workflows.

---

# Automatic Language Discovery

One of MCF's core features is automatic language discovery.

During application startup, MCF recursively scans every Workflow.

Whenever a Lang directory is found, its translation resources are registered automatically.

Developers never manually register language paths.

---

# Registration Process

The localization lifecycle is straightforward.

```text
Application Startup

↓

Discover Modules

↓

Discover Workflows

↓

Locate Lang Directories

↓

Register Translation Resources

↓

Translations Become Available
```

Every Workflow participates automatically in this process.

---

# Self-Contained Workflows

Because each Workflow owns its own localization resources:

- Moving a Workflow also moves its translations.
- Copying a Workflow copies its translations.
- Removing a Workflow removes its translations.
- Importing a Workflow imports its translations.

No additional configuration is required.

---

# Advantages

Workflow-based localization provides several benefits.

- Better project organization.
- Independent features.
- Reduced merge conflicts.
- Easier maintenance.
- Improved modularity.
- Cleaner repositories.
- Better scalability.

As applications grow, translations remain distributed instead of accumulating in one location.

---

# Remove Language Resources

Generated language resources may be removed.

Remove an entire locale.

```bash
php artisan mcf:lang:remove <locale>
```

Example:

```bash
php artisan mcf:lang:remove ar
```

---

Remove localization for one Module.

```bash
php artisan mcf:lang:remove <locale> <module>
```

Example:

```bash
php artisan mcf:lang:remove ar Users
```

---

Remove localization for one Workflow.

```bash
php artisan mcf:lang:remove <locale> <module> <workflow>
```

Example:

```bash
php artisan mcf:lang:remove ar Users Profile
```

Only the selected translation resources are removed.

---

# Best Practices

When working with localization:

- Keep translations inside their owning Workflow.
- Generate language resources using the CLI.
- Avoid creating global feature-specific language files.
- Use descriptive translation keys.
- Keep translations synchronized across supported locales.
- Remove unused localization resources when deleting Workflows.

Following these practices keeps localization organized and maintainable.

---

# Relationship to Workflows

Localization is considered part of the Workflow itself.

Example:

```text
Profile

├── Backend
├── Views
└── Lang
```

Just like Views belong to a Workflow, its translations also belong to that Workflow.

This reinforces MCF's philosophy of self-contained business features.

---

# Laravel Compatibility

MCF builds on Laravel's localization system.

Translation resources generated by MCF are registered automatically during application startup, allowing developers to use Laravel's standard localization features without additional configuration.

The framework changes only how localization is organized—not how translations are accessed.

---

# Summary

The Language Generator simplifies localization by creating translation resources directly inside each Workflow.

Combined with MCF's automatic language discovery, this approach removes manual registration, keeps features self-contained and ensures that localization scales naturally as applications grow.
